# Agent instructions

Kuchsistent: Czech household cooking assistant (recipe photos → meal plan → shopping list). TanStack Start (SPA mode) + Convex + Convex Auth v2, deployed on Vercel. Read `README.md` and `GLOSSARY.md` first, and use the glossary's terms.

## Taking a ticket ("implement issue N")

1. Read the issue, its acceptance criteria, and the **resolution comment** of every decision ticket it links (those comments are the source of truth). Also read the closing comments of finished build tickets it depends on (e.g. #14) for setup notes.
2. Assign the issue to `cajkavlada` so parallel sessions skip it.
3. Branch from the latest `main`: `feat/<N>-<slug>`.
4. Build the whole vertical slice: schema, Convex functions, UI, tests.
5. Before opening the PR, and again whenever told another PR was merged: rebase onto the latest `main`, resolve conflicts, run `npm run codegen`, `npm run typecheck`, `npm test`, and a placeholder build (`VITE_CONVEX_URL=https://x-1.convex.cloud npm run build`).
6. Open the PR (body: what was built, notes for review, "Part of #N" / "Implements #N"), then tell the user what to test on the phone and which Convex env vars, if any, they must set. Don't close the issue: the user closes it after the phone demo.

Branches named `prototype/*` and `research/*` are reference only. Read them, never merge them.

## Sandbox limits (Claude Code cloud sessions)

- **No Convex backend is reachable** (`*.convex.dev`, `*.convex.cloud` are blocked). `npx convex dev`, `npx convex codegen` and `npx convex deploy` fail. Instead run `npm run codegen` (`scripts/codegen-offline.mjs`) after adding or removing any module in `convex/`; it rewrites `convex/_generated`. If you mount a new component or declare a new env var in `convex/convex.config.ts`, update `COMPONENTS` / `ENV_VARS` at the top of that script. Vercel's build regenerates `_generated` for real on deploy.
- Files in `convex/` with more than one dot (`*.test.ts`, `test.setup.ts`) are not deployed; keep test helpers named that way.
- Test backend logic with vitest + `convex-test` (`convex/*.test.ts`, see `convex/households.test.ts`). Code that calls `getAuthUserId` needs the auth component; test the logic through a helper that takes `userId` (like `createHouseholdFor`) via `t.run`, and only test "not signed in" through the public function.
- **GitHub GraphQL is blocked**, so `gh pr create`, `gh issue view` etc. fail. Use REST: `gh api repos/cajkavlada/kuchsistent/...` (e.g. `gh api repos/cajkavlada/kuchsistent/pulls --input pr.json`).
- Push with `git -c push.negotiate=true push -u origin <branch>`.
- Headless Chrome is available (`google-chrome --headless=new --screenshot=… --window-size=412,860`) to look at screens served from a build (`PORT=3100 node .output/server/index.mjs`). Without a backend only the signed-out screen renders.

## Code conventions

- UI strings and data are **Czech**; code, comments, issues, PRs and docs are **English**.
- Every public Convex function that touches Household data starts with `requireMember(ctx)` (`convex/lib/membership.ts`) and scopes all reads and writes to the returned `household`; check loaded docs with `assertSameHousehold`. Errors are `ConvexError({ code })`; map codes to Czech messages in the UI.
- Calendar days are Europe/Prague `YYYY-MM-DD`: use `convex/lib/dates.ts` on client and server, never `toISOString()` for a day.
- Use `ctx.db.get("table", id)` / `ctx.db.patch("table", id, …)` (table-name form).
- Frontend imports Convex code via `@convex/*`, app code via `~/*`. Routes live in `src/routes` (file-based; `src/routeTree.gen.ts` is generated by the build, commit it). New tabs/pages go inside the `AppLayout` shown by `src/components/Gate.tsx`.
- Target device: Android phone, Chrome. Design for a ~400 px wide touch screen.

## Auth and deploy facts

- Convex Auth v2 is component-based: `convex/convex.config.ts` mounts `auth` and `authGoogle`; `convex/auth.ts` wires the Google method; users are created in `convex/users.ts`. Google's callback is `<CONVEX_SITE_URL>/oauth/google/callback`.
- OAuth must return to a page that doesn't redirect (currently `/plan`); a redirect drops the `code` param and sign-in silently fails.
- Convex env vars: `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`, `SITE_URL`, `HOUSEHOLD_CREATOR_EMAILS`. `SITE_URL` is read when modules load, so a change needs a redeploy. Never use the `VITE_` prefix for secrets.
- Every PR gets a Vercel preview with its own Convex preview backend, recreated empty on every push (`scripts/vercel-build.sh`) and seeded by `seed:preview` in `convex/seed.ts` (add sample data there when useful). Google sign-in can't complete on previews; `seed:preview` turns on a fake "Testovací přihlášení" (Tester A/B/C, `convex/testLogin.ts`) so PRs can be tested on a phone. Previews sit behind Vercel deployment protection. Production: https://kuchsistent.vercel.app (Vercel functions in `fra1`).
